# Adversarial review: is dsh-eval-infra really ahead on every scorecard row?

Review date: 2026-09-04. Target claim (docs/sota-scorecard.md, "Verdict"): *for paired evaluation of a dsh component change, no surveyed tool or method is ahead on any row of sections A–D, F or G.*

## 0. Inputs and method

- Read: `docs/sota-scorecard.md`, `docs/landscape.md`, `docs/methodology.md`, plus `docs/results.md`, `README.md`, and read-only greps of `src/` to avoid raising objections the code already answers. **`docs/landscape-2.md` and `docs/methodology-2.md` do not exist in the repo**, although the scorecard header lists both as sources and the verdict cites "two landscape sweeps" and "two literature sweeps". The second sweeps are therefore unverifiable from the repository.
- Fresh lookups (all 2026-09-04): 19 GitHub search queries and ~25 repository/PR/README reads via `gh api`, 11 web searches, ~30 page fetches (release pages, changelogs, arXiv abstracts, two arXiv API listings). Window of interest: 2026-08-15 → 2026-09-04.
- Conventions below: "equal" = the challenger matches the row, so the row is not *behind* but the verdict's "no tool combines…" wording is weakened; "ahead" = the challenger does something the row does not.

## 1. Headline findings

1. **The survey never looked at its own ecosystem.** `landscape.md` contains zero mentions of any dsh-native evaluation tool (grep count 0), yet at least seven exist, and one of them (`muou000/dsh-eval`, pushed 2026-09-01) already implements the scorecard's signature design: seeded first order then strict AB/BA alternation, serialized pairs, pre-registered gates, SHA-256 content-addressed artifacts and fail-closed manifests. Another (`dsh-plugin-evaluation`) runs Docker-only; another (`dsheval.ai`) publishes a public plugin-evaluation ledger. Section 2 gives URLs.
2. **The scorecard contradicts the shipped code and the results log.** It marks judge panels and PPI as *missing* and container isolation as *partial*, and its verdict says "prediction-powered inference, judge panels across model families and conformal abstention are not [implemented]". But `src/core/judge.ts` implements a strict-majority panel and PPI++ (lines 37, 258–301), `src/cli.ts:345` documents `--sandbox docker`, and `docs/results.md` logs runs of all three on 2026-09-04. A SOTA claim cannot be assessed while the self-description is wrong in both directions.
3. **Several surveyed tools moved after the survey.** Inspect AI 0.3.261 (2026-08-30) and 0.3.262 (2026-09-02) shipped a multi-model judge panel with majority vote, `ci_wilson()` with effective-sample-size clustering and a `ci()` metric; Harbor v0.21.0/v0.22.0 (2026-08-10/22) shipped trial re-grading, task lockfiles and simulated-user multi-turn trials, and merged a KVM microVM environment on 2026-08-31; Langfuse v4.27.0 (2026-09-01) added cached-token cost; promptfoo 0.122.1 (2026-08-26) added grading-token accounting; Braintrust added blind human review. The landscape entries for these tools are stale.
4. **Statistical and protocol soft spots that published work already handles better:** an asymptotic confidence sequence is read at n = 6 on the cost metric; the judge is from the same model family as both arms (the code comment admits it); cost evidence is self-reported by the process under test; there is no perturbation floor, no served-model verification, no judge-drift attribution, no fault injection, no re-grade of stored trials.

## 4. What survived the attack

For balance: no tool found does calendar-band re-pricing (C2); the one-variable composed-tree diff with refusal (A3) has no exact equal (muou000 pins the variant but does not diff a composed config); the correctness-gate-before-cost ordering with cost compared only on both-pass pairs (D1–D2) is unique in wording, though ClawBench's "judge can never rescue a failed deterministic check" and BiBoyang's gate are close; McNemar mid-p with a Beta posterior and ROPE (D8, D11) is not offered by any surveyed product; the anytime-valid sequential mode (A8) is ahead of every *product* surveyed even if behind the papers on finite-sample validity. The "Harness Engineering" paper (2609.00006) is a source-code study and offers no comparison protocol, so it does not threaten any row.

## 5. Ranked objections (strongest first)

1. **The survey ignored the dsh ecosystem, and at least one dsh-native tool already implements the scorecard's core design.** Evidence: https://github.com/muou000/dsh-eval (seeded AB/BA alternation, serialized pairs, pre-registered thresholds, SHA-256 artifacts, fail-closed manifests, Wilson intervals, per-pair regressions), https://github.com/hccccc01333/dsh-eval (paired A/B, keyless replay, cross-harness import), https://github.com/BiBoyang/dsh-eval-harness, https://github.com/dsh-plugin-evaluation/dsh-plugin-evaluation-platform, https://dsheval.ai/dsheval; `grep` of landscape.md for any of them returns 0. To answer: add a "dsh-native tools" section to the landscape with a row-by-row comparison, and either adopt content-addressed artifacts plus fail-closed manifests or show equivalence.
2. **The scorecard misdescribes the shipped tool (panel, PPI++, Docker), so the verdict is not about the artefact that exists.** Evidence: src/core/judge.ts:37 and :258–301, src/cli.ts:345, docs/results.md entries "judge panel and absolute grades" and "docker-check" vs scorecard rows E1/E2/F1 and the verdict paragraph; the cited `landscape-2.md`/`methodology-2.md` are absent. To answer: regenerate the scorecard from the code, mark each row with the dsh version and run id that exercised it, and commit the second sweeps.
3. **Cost verdicts rest on usage self-reported from inside the process hosting the component under test.** Evidence: https://github.com/muou000/dsh-eval/blob/main/docs/ARCHITECTURE.md ("Reports label it `trust: self-reported`; local token/cost release gates fail closed"), https://github.com/minghinmatthewlam/openbench/blob/main/docs/harbor-metering.md (sealed, hash-chained CountingProxy ledger). To answer: add a proxy-side or provider-billing reconciliation ledger, label usage provenance in the report, and refuse a cost verdict when the two disagree beyond a tolerance.
4. **The cost sequence is an asymptotic confidence sequence read at n = 6.** Evidence: src/core/stats.ts:271 (`asympCS`, `plannedN = 10`), docs/results.md sequential-check (decisions at n = 2…6); https://arxiv.org/abs/2103.06476 ("forgo nonasymptotic validity"); https://arxiv.org/abs/2608.06362 (AsympCS for screening, empirical-Bernstein CS for "exact finite-sample certification"). To answer: add an empirical-Bernstein or betting CS on bounded cost ratios as the deciding sequence, or refuse to read AsympCS below a stated n, and report both.
5. **The judge protocol breaks the project's own methodology.** Evidence: src/core/orchestrate.ts:322 ("same family: a stated limitation"), methodology §C4 (judge family must differ from both arms and the author model), https://arxiv.org/abs/2502.01534, https://arxiv.org/html/2404.13076; no TPR/TNR (https://github.com/BiBoyang/dsh-eval-harness), no abstention (https://arxiv.org/abs/2602.13110), no length control, no anchor-set drift attribution (https://arxiv.org/abs/2606.15474), no panel error-correlation (https://github.com/itsjustmarsel/llm-judge-independence). To answer: refuse same-family judges by default (the `family` field already exists in src/core/project.ts:21), report TPR/TNR and error correlation, add conformal abstention and an anchor set.
6. **Isolation is behind and the mitigation is contradicted by the vendor.** Evidence: https://github.com/deepseek-ai/deepseek-harness/blob/main/SAFETY.md, https://github.com/harbor-framework/harbor/pull/2998 (Kata microVM), https://github.com/dsh-plugin-evaluation/dsh-plugin-evaluation-platform (Docker-only), docs/results.md docker-check (in-process sandbox replaced by plain bash inside the container). To answer: make the container path the default for third-party plugins, keep dsh's sandbox active inside it (or document why not), and publish the escape-probe results as an artifact.
7. **Rows marked "met" have no logged real run, violating the scorecard's own rule.** Evidence: docs/results.md contains no run for CUPED, `--include-holdout`, flaky retirement, `--max-usd` cancel/`--resume`, and every run used 1–2 repeats against a floor of 3. To answer: log one run per row (with run id) or downgrade those rows to *partial*.
8. **Verifier-side and scenario-side capabilities the field now has are missing entirely.** Evidence: re-grade of stored trials (https://github.com/harbor-framework/harbor/pull/2358), perturbation floor (https://arxiv.org/html/2608.22331), fault injection (https://arxiv.org/abs/2601.06112), SNR-based task curation (https://github.com/openclaw/shellbench), discovery/confirmation split (https://arxiv.org/abs/2608.30916), simulated user (https://github.com/harbor-framework/harbor/pull/2405), served-model verification (https://arxiv.org/abs/2609.00052). To answer: add rows for each with status *missing* and prioritise regrade, perturbation floor and fault injection, which are cheap given the existing ledgers.

Bottom line: the narrow claim ("no surveyed tool is ahead on any row of A–D, F, G") fails on A5, A7, A8, B1, B2, B6, C4, C6, D13, E1, E3, F1 and F3 against tools and papers that exist today, and the survey's universe omitted the tool's own ecosystem. The unique combination the verdict describes is real, but it is a combination, not a lead on each row.
